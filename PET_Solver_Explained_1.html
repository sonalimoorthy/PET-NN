1The big picture

This notebook trains a small artificial "brain" (a neural network) to do one job: given four numbers describing the weather around a person, instantly estimate a temperature that captures how hot it feels to the body.

There is already a trusted tool that computes this feeling-temperature exactly — but it's slow, because it solves physics equations one condition at a time. The notebook's whole goal is to build a fast stand-in (called a surrogate model) that gives almost the same answer in a tiny fraction of the time.

Analogy

Imagine a master chef who can taste any soup and tell you its exact spiciness — but takes 10 minutes per bowl. This notebook trains an apprentice by having them taste 40,000 bowls the chef already rated. Afterwards, the apprentice guesses the spiciness of a new bowl instantly, and is almost never wrong. The chef is the physics solver; the apprentice is the neural network.

2What is PET?

PET stands for Physiological Equivalent Temperature. It's a single number, in degrees Celsius, that answers a very human question: "How hot or cold does it actually feel to a person standing here?"

The plain thermometer reading isn't enough. 30°C in dry, breezy shade feels totally different from 30°C in humid, still, blazing sun. PET rolls all of those effects into one honest number. If PET is 41°C, it means your body reacts as if it were a still, standard room at 41°C — even if the thermometer says something else.

To compute PET, the model needs four pieces of information about the environment:

SymbolMeaningEveryday translationRange used here
tdbAir temperature (dry-bulb)What a normal thermometer reads10 – 50 °C
trMean radiant temperatureHeat radiating off sun, walls, pavement10 – 80 °C
vAir/wind speedHow much of a breeze there is0.0003 – 10 m/s
rhRelative humidityHow muggy/damp the air is30 – 100 %

Many other things affect PET too — a person's age, clothing, activity level, height, weight, and so on. In this notebook those are all frozen to fixed values (a 35-year-old man, lightly dressed, sitting, doing light activity). So the model only has to learn how PET changes with the four weather variables. That keeps the problem focused.

3Why build this at all?

The reference tool used here is a Python library called pythermalcomfort, and its pet_steady function computes PET the "proper" way — by iteratively solving heat-balance equations for the human body until they settle. That's accurate, but it means:

  • It's slow — every single condition requires an iterative solve.
  • It handles one condition at a time, which is painful if you need PET for millions of points (say, a heat map of an entire city, or a climate simulation).
  • It can fail to converge in extreme conditions (more on that later).

A neural network, once trained, computes its answer as a fixed sequence of multiplications and additions — no iteration, no searching. It can also process thousands of conditions simultaneously on modern hardware. The trade-off is a tiny bit of accuracy for an enormous speed gain, which for most applications is a great deal.

The payoff, measured at the end of the notebook: the network matches the physics tool to a fraction of a degree, while running roughly a thousand times faster across the 10,000-sample test set.

6The "teacher" solver

This is the ground-truth source of answers — the master chef. The notebook wraps pet_steady in a small helper so the rest of the code can just call pet_reference(tdb, tr, v, rh) and get back a PET value, without worrying about the physiological settings (which are pinned to the fixed values from the last section).

def pet_reference(tdb, tr, v, rh):
    """Ground-truth PET for one weather condition."""
    try:
        res = pet_steady(tdb=tdb, tr=tr, v=v, rh=rh, met=MET, clo=CLO, ...)
    except (TypeError, ValueError):
        # older versions of the library expect number codes instead
        # of words ("sitting" → 1, "male" → 1) — handle both
        res = pet_steady(..., position=pos_code, sex=sex_code, ...)
    return float(res.pet) if hasattr(res, "pet") else float(res)

The try / except block is a robustness trick. Different versions of pythermalcomfort accept slightly different arguments. Rather than break on one version, the code tries the modern way first, and if that fails, falls back to the older style. It's the programming equivalent of "if the door's locked, try the side entrance."

7Generating training data

The network can only learn from examples, and this section manufactures them. The recipe is simple in spirit:

  1. Pick four random numbers (a random weather condition) within the allowed ranges.
  2. Ask the teacher (pet_reference) what the correct PET is.
  3. Store the pair: (inputs → correct answer).
  4. Repeat 30,000 times for training, 10,000 more for testing.

The training set and test set are drawn independently. This matters: the test set acts like a surprise exam. If the model only did well on data it had already seen, we'd learn nothing about whether it truly understands the pattern. Grading it on fresh, unseen conditions is the honest test.

for i in range(n):
    while True:
        tdb = rng.uniform(TDB_MIN, TDB_MAX)   # random draw
        tr  = rng.uniform(TR_MIN,  TR_MAX)
        v   = rng.uniform(V_MIN,   V_MAX)
        rh  = rng.uniform(RH_MIN,  RH_MAX)
        if rh > safe_rh_max(tdb):
            continue            # outside safe zone → redraw
        pet = pet_reference(tdb, tr, v, rh)
        if warned:               # solver didn't converge → redraw
            continue
        break                    # got a clean answer, keep it
    X[i] = [tdb, tr, v, rh]
    y[i] = pet

Notice the two ways a random draw can get rejected and redrawn: if it falls outside a "safe zone," or if the physics solver stumbles. Both are about keeping the training data clean — explained next.

8The safe-zone boundary

Here's a real-world wrinkle. The physics solver works by iterating toward an answer. In some extreme combinations — think very hot AND very humid at the same time — the equations don't settle down. The solver throws a RuntimeWarning: essentially "I couldn't converge on a reliable answer here."

Training a network on unreliable answers would teach it nonsense. So the notebook avoids those regions in two layers:

Layer 1: the safe-zone boundary

A geometric rule that keeps sampling away from the danger area. Humidity is allowed all the way up to 100% while it's cool, but as air temperature climbs past 35°C, the allowed humidity is squeezed downward — from 100% at 35°C down to 50% at 50°C, along a straight line.

Layer 2: resample-on-warning

Even inside the safe zone, the occasional draw might still trip the solver. Whenever that happens, that draw is thrown away entirely and all four inputs are redrawn — not patched or nudged. Only fully clean, converged answers make it into the dataset.

Analogy

Think of a hiking map with a shaded "no-go" swamp in one corner. The safe-zone boundary is a fence drawn well clear of the swamp so hikers rarely wander in. But if someone still sinks into a soft patch inside the fence, they don't try to trudge through — they go back and pick a completely new route. That's exactly the two-layer strategy.

The notebook even visualizes this: it plots which temperature-and-humidity combinations triggered warnings (in red) versus which were fine (in blue), with the boundary line overlaid, so you can literally see that the fence sits where it should.

9Preparing the numbers (scaling)

Neural networks learn best when all their inputs live on a similar, small scale — roughly between 0 and 1. Feeding raw numbers like "temperature = 50" next to "wind = 0.0003" makes learning lopsided. So every input is rescaled:

tdb  → tdb / 100      # 10–50 becomes 0.1–0.5
tr   → tr  / 100
v    → v   / 10
rh   → rh  / 100      # 30–100 becomes 0.3–1.0
pet  → pet / 100      # the answer is scaled too

A clever extra input: log_v

Wind speed ranges from 0.0003 to 10 — a span of over four orders of magnitude. If you just divide by 10, then almost every low-wind value (0.001, 0.01, 0.1...) gets crushed into a tiny sliver near zero, and the network can't tell them apart — even though those differences matter a lot for how it feels.

The fix is to add a fifth input: the logarithm of wind speed, rescaled to 0–1. A logarithm "stretches out" the small values so the low-wind regime gets proper resolution. This is a piece of feature engineering — giving the network a smarter view of the same data.

Analogy

It's like a volume knob. On a linear scale, whispers (0.001) and rustles (0.01) look identical — both "basically silent." A logarithmic scale is how our ears actually work: it spreads those quiet sounds apart so you can distinguish them. The network gets both the plain wind value and this "log volume knob" version.

So the network actually receives five numbers per condition: tdb, tr, v, rh, and log_v.

10The neural network

Now the "brain" itself. It's a Multi-Layer Perceptron (MLP) — the classic type of neural network, essentially a stack of layers where each layer transforms its inputs and passes them on. This one has a distinctive two-branch design:

🌡️ Temperature branch

Takes the two temperature-related inputs — air temperature tdb and radiant temperature tr — and processes them together through a couple of layers.

💨 Air branch

Takes the "air quality" inputs — wind v, humidity rh, and the engineered log_v — through their own couple of layers.

The two branches are then merged and passed through more shared layers, before a final layer squeezes everything down to a single number: the predicted PET.

class MLP:
    width = 256
    def __call__(self, inputs):
        Tdb, Tr, V, Rh, LogV = split(inputs)      # separate the 5 inputs

        Temps = stack([Tdb, Tr])                     # temperature branch
        Temps = silu(Dense(128)(Temps))
        Temps = silu(Dense(256)(Temps))

        Air = stack([V, Rh, LogV])                   # air branch
        Air = silu(Dense(256)(Air))
        Air = silu(Dense(256)(Air))

        merged = stack([Temps, Air])                 # combine
        merged = silu(Dense(256)(merged))
        merged = silu(Dense(256)(merged))
        return Dense(1)(merged)                       # one number out: PET

Two terms worth unpacking:

  • Dense layers are the building blocks — each mixes all its inputs together with learnable weights. width = 256 means each layer has 256 internal "neurons," giving the network capacity to represent a rich function.
  • SiLU activation is the "spark" between layers. Without a nonlinear activation, stacking layers would collapse into plain straight-line math and couldn't capture PET's curved behavior. SiLU is a smooth, gently-curved function well-suited to this.

A documented dead-end (and why it's valuable)

The notebook records that an earlier attempt used a sinusoidal (SIREN-style) activation — and it failed badly, essentially predicting the average every time (accuracy score near zero, ~11°C off). The reason: sine-wave activations are designed for high-frequency, wiggly signals like images and audio. PET is a smooth, gently-varying function, and forcing sine waves onto it made the learning landscape needlessly jagged. Switching to SiLU fixed it. Documenting what didn't work is a mark of careful engineering.

Step 1 — Where the numbers come from

During data generation, each input is drawn from a uniform distribution — meaning every value in the allowed range is equally likely, like rolling a perfectly fair die. There's no bias toward the middle or the edges; the draws spread evenly across the whole box of possibilities. Draws that land outside the safe zone (or trip the solver) are discarded and redrawn, as covered earlier.

Step 2 — Scaling turns 4 numbers into 5

As shown in the previous section, these get rescaled to sit between 0 and 1, and the extra log_v feature is appended. Our example becomes the input vector the network actually sees:

Five scaled inputs — this row of numbers is what enters the network.

Step 3 — What one neuron actually does

Before the whole network, understand its atom: a single neuron. It's surprisingly simple. It takes several inputs, multiplies each by its own weight (a learned importance), adds them all up together with a bias (a learned offset), and passes the total through an activation function that adds a gentle curve. That's it.

One neuron: weigh each input, sum with a bias, then bend through an activation. A "Dense layer of width 256" is simply 256 of these neurons side by side, each with its own weights.
Analogy

A neuron is like a judge scoring a dish. Each ingredient (input) matters a different amount — the weights are how much the judge cares about salt vs. spice vs. texture. The judge sums up a total impression, adds a personal baseline mood (the bias), and gives a final score. Training is teaching thousands of these judges the right amount to care about each thing.

Step 4 — The activation function (SiLU)

Why bend the number at all? Because without a curve, stacking layers is pointless — a pile of straight lines is still just one straight line, and PET is not a straight-line function. The activation injects the gentle curvature that lets the network bend and shape its output to match reality. This model uses SiLU (also called Swish), shown here:

SiLU: near-zero (with a slight dip) for negative inputs, smoothly ramping up toward a straight line for large positive inputs. Smooth everywhere — no sharp corners — which keeps training stable.

Step 5 — The full network, layer by layer

Now the complete architecture. The five scaled inputs split into two branches that process temperature and air separately, then merge and pass through shared layers before collapsing to a single PET value. Each blue block is a Dense layer followed by a SiLU activation.

The two-branch MLP. Temperature inputs (blue) and air inputs (green) are processed in parallel, merged (orange), refined, then squeezed to a single PET value (purple). Numbers like "256" are the layer widths — how many neurons each layer holds.

Why split into two branches?

Temperature (tdb, tr) and air conditions (v, rh, log_v) affect the body through different physical mechanisms — radiant/conductive heat versus evaporative cooling and convection. Letting each branch first build its own specialized understanding before combining tends to learn cleaner, more efficient representations than throwing all five numbers into one undifferentiated pile. The branches only "talk" to each other after each has done its initial processing.

Step 6 — Out the other end

The final Dense 1 layer produces a single scaled number. Multiply it back by 100 (the reverse of the output scaling) and you have the predicted PET in real degrees Celsius. For our tracked example the network returns a value very close to what the slow physics solver would give for (30, 40, 1.0, 50) — but in a fraction of the time.

12How it learns (training)

Training is the process of gradually adjusting the network's internal weights until its guesses match the teacher's answers. The loop, in plain terms:

  1. Guess: the network predicts PET for a batch of training examples.
  2. Measure the error: compare guesses to correct answers using Mean Squared Error (the average squared gap — squaring punishes big mistakes more).
  3. Learn: the optimizer (Adam) nudges every weight slightly in the direction that would have reduced the error.
  4. Repeat across all data — that's one epoch — and do 1,200 epochs total.
Analogy

Picture rolling down a foggy hill trying to reach the lowest valley (lowest error). You can't see the bottom, but you can feel which way is downhill under your feet, and step that way. Each step is one update; the "steepness under your feet" is the gradient. Adam is a smart hiker that remembers recent steps so it doesn't zig-zag wildly.

The learning-rate schedule

How big each step should be (the learning rate) isn't fixed. The notebook uses a warmup-then-cosine-decay schedule:

  • Warm up gently from a small step size (avoid crashing early),
  • peak at a larger step to cover ground quickly,
  • then slowly shrink the steps toward the end for fine, precise tuning.

It's like sprinting across open ground but tiptoeing as you close in on the exact target.

Watching the progress

A slice of the training data (10%) is held back as a validation set. Every few epochs the notebook checks error on it and plots two curves:

  • the training loss (should steadily fall), and
  • the validation MAE in real degrees, against a target line of 0.08°C.

Speed note: the notebook mentions a big optimization — instead of dispatching hundreds of thousands of tiny individual training steps (slow), it runs each epoch as a single fused operation on the hardware (jax.lax.scan). Same math, dramatically faster wall-clock time. This is an engineering detail, not a change to what's being learned.

13Does it work? (evaluation)

After training, the network faces the 10,000-example surprise exam. Several complementary measures are reported:

MetricWhat it tells you
MAE (°C)Mean Absolute Error — on average, how many degrees off is it? Lower is better.
RMSE (°C)Like MAE but penalizes large misses more heavily.
Max abs error (°C)The single worst mistake across all 10,000 cases — the "worst-case" guarantee.
Relative L2 error (%)Overall error as a percentage of the signal size.

The visual checks

  • Parity plot: network prediction vs. true PET for every test point. If perfect, all dots land on the diagonal line. A tight cloud hugging that line means excellent agreement.
  • Error histogram: the spread of mistakes. A narrow spike centered on zero means errors are small and unbiased (not systematically too high or too low).
  • PET-vs-temperature sweeps: curves showing how predicted PET rises with air temperature at different wind speeds — a sanity check that the model behaves physically (hotter air → higher PET, more wind → lower PET).

The takeaway the notebook is designed to demonstrate: the surrogate reproduces the physics tool to within a fraction of a degree, with an R² essentially at 1.0, while being about three orders of magnitude faster. That's the whole point proven.

Saving the trained model

The learned weights are written to a file (model/model_pet_solver.pickle) with Python's pickle. This freezes the finished "brain" to disk so it can be reloaded and reused later without retraining — training happens once; using it happens forever after.

14Using the finished model

A convenience function pet_nn(tdb, tr, v, rh) wraps everything up so a user never has to think about scaling or the extra log_v feature. You hand it plain weather numbers; it handles the rescaling internally, runs the network, and unscales the answer back into real degrees:

tdb, tr, v, rh = 30.0, 40.0, 1.0, 50.0
print("NN PET       :", pet_nn(tdb, tr, v, rh))       # the fast estimate
print("Reference PET:", pet_reference(tdb, tr, v, rh)) # the slow truth

Running both side by side lets you confirm the two agree closely — the apprentice and the chef tasting the same bowl and giving nearly the same score.

It also works on whole arrays at once: give it 10,000 conditions and it returns 10,000 PET values in a single fast pass. That batch ability is exactly what makes it useful for large-scale applications like city-wide heat mapping.

Why this matters

This is the "show your work" section. Rather than just asserting "we avoided bad regions," the author empirically maps where the trouble is and proves the chosen boundary handles it. It's the difference between saying "trust me" and showing the evidence.

16Glossary

PET (Physiological Equivalent Temperature)
A single °C number for how hot/cold the environment feels to a standard person, folding in air temperature, radiant heat, wind, and humidity.
Surrogate model
A fast, learned stand-in that mimics a slow, exact calculation. Trades a little accuracy for a lot of speed.
Neural network / MLP
A stack of layers of simple units with adjustable weights, trained to map inputs to outputs by example. MLP is the standard, straightforward kind.
Feature engineering
Creating smarter versions of the inputs to help the network learn — here, adding log_v so tiny wind speeds are distinguishable.
Scaling / normalization
Rescaling all inputs to a similar small range (≈0–1) so no single input dominates and learning stays balanced.
Activation function (SiLU)
The nonlinear "spark" between layers that lets the network model curved relationships instead of just straight lines.
Optimizer (Adam) & learning rate
Adam is the algorithm that adjusts weights during training. The learning rate is how big each adjustment step is; here it warms up, peaks, then decays.
Epoch
One full pass through all the training data. This notebook does 1,200.
Loss (MSE)
The number being minimized during training — Mean Squared Error between predictions and truth.
MAE / RMSE / R²
Accuracy scores. MAE = average error in °C; RMSE punishes big misses; R² = fraction of variation captured (1.0 is perfect).
Validation set / test set
Data held back from training to honestly judge performance. Validation guides training; the test set is the final surprise exam.
RuntimeWarning / convergence
The physics solver iterates toward an answer; in extreme conditions it can't settle ("doesn't converge") and warns. Those cases are excluded from training.
Seed
A fixed starting point for randomness so the whole notebook reproduces identically on every run.
